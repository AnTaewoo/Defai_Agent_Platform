# 아키텍처 결정 기록 (LOCKED)

## ADR-1. 단일 검색엔진 (OpenSearch)
- **결정:** 키워드(BM25) + 벡터 검색을 OpenSearch 한 엔진으로 통합. k-NN 플러그인 + ML Commons.
- **이유:** Apache 2.0 라이선스로 기업/기관 도입 자유. 별도 벡터 DB 구축·운영 비용 제거. 스택 단순화.
- **거부안:** Pinecone, Milvus, Chroma 등 전용 벡터 DB.

## ADR-2. 파싱 로직 직접 제어
- **결정:** LangChain은 로딩~저장 전처리 체인 접착제로만. 핵심 파서는 자체 구현.
- **이유:** 프로덕션 디버깅 용이성. HWP·복잡한 표·스캔본은 추상화 레이어에서 통제 불가능한 엣지케이스 다발.

## ADR-3. 하이브리드 배치
- **결정:** 주기적 수집/재인덱싱 = Airflow DAG. 실시간 업로드 반영 = 자체 트리거.
- **이유:** 정기성과 즉시성을 모두 충족.

## ADR-4. LangGraph 오케스트레이션
- **결정:** 질의분류·에이전트 라우팅·재검색 판단 등 조건부 분기/루프 흐름을 LangGraph로.
- **이유:** 멀티에이전트 상태/분기 제어에 최적.

## ADR-5. 권한 = 인덱싱 시점 메타데이터 + 쿼리 pre-filter
- **결정:** 청킹 때 보안등급/부서/에이전트 태깅. 검색 쿼리 filter 절에 권한 강제 주입.
- **이유:** 후처리 필터링은 데이터 누출 위험. 보안이 최우선 가치인 국방 도메인.

## ADR-6. 로컬 LLM 서빙 (vLLM) + admin 클라우드 토글 예외
- **결정:** 생성 LLM 기본값은 **오픈웨이트 모델을 vLLM으로 사내 서빙**한다(망분리 기본). 외부 클라우드 LLM API(Anthropic/OpenAI 등)는 **기본 금지**이되, **admin 전역 토글(on-prem↔cloud)** 로만 활성화되는 명시적 예외를 둔다(경고·확인·전수 audit). 임베딩은 항상 local(ML Commons).
- **이유:** 온프레미스·망분리·기밀(등급5) 데이터 주권이 기본. 단 운영 현실상 고품질 클라우드 모델이 필요한 경우를 위해, 데이터 반출 위험을 admin이 명시적으로 감수·기록하는 게이트형 예외를 제공한다(차단이 아니라 책임·감사).
- **인터페이스:** vLLM의 **OpenAI 호환 엔드포인트**(`/v1/chat/completions`)를 사용. 코드상으론 "API 호출"이지만 기본 네트워크 경계는 사내. cloud 토글 시에만 외부로 나간다.
- **등급 라우팅 (config 기반):** `security_level → endpoint` 매핑으로 LLM을 호출한다.
  - 전 등급이 같은 엔드포인트 → **단일 서빙**
  - 등급별 다른 엔드포인트/GPU 노드 → **물리 분리**
  - 둘 다 코드 변경 없이 설정(`llm_endpoints`)으로 전환 가능. (현재 기본값: 단일 엔드포인트, 추후 분리 가능 구조)
- **불변식:** LLM 호출도 검색과 마찬가지로 `Principal` 없이는 불가. 등급에 맞지 않는 엔드포인트로는 호출되지 않는다. **소스 모드(on-prem/cloud)는 admin 전역 설정이며 전환·cloud 중 L3↑ 진행은 전부 `audit_log`에 남는다.** 기본 상태에서 외부 LLM 호출 0건(EGRESS 0).
- **에이전트 등급 = 모델 등급:** 모델을 vLLM으로 서빙할 때 보안등급을 지정하면, 그 모델을 쓰는 에이전트의 `security_level`이 자동 부여된다. 유저는 자기 클리어런스 이상 등급의 에이전트를 자동으로 못 본다(수동 유저별 허용 없음).
- **거부안:** 외부 클라우드 LLM **무게이트 상시 사용**(기밀 반출 위험 — 토글·audit 게이트로만 허용), Ollama 단일 인스턴스(동시성·서빙 처리량 부족).

## 데이터 저장 분담
- 정형 메타데이터(사용자, 권한, 에이전트 설정, LLM 엔드포인트 매핑): PostgreSQL / MariaDB
- 문서 청크 + 임베딩 + 검색 메타: OpenSearch
